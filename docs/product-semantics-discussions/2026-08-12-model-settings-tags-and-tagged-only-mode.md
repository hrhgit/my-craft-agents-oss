# 模型设置页重构：多默认 → 标签体系与仅显示标签模型

状态：已达成共识（读图代理模型部分为待决定）

开始时间：2026-08-12 14:30 CST (UTC+08:00)

结束时间：2026-08-12 15:40 CST (UTC+08:00)

## 背景

设置页“模型”页当前支持“增加多个默认”（`defaultSlots`，slot 1..N）。用户希望移除该功能，改为模型标签体系：给模型打标签（常用、快速、轻量等），带标签的模型在会话页选择时显示标签；设置页提供“仅显示标签模型”开关，开启后会话页切换模型只显示带标签的模型，并以单级列表展示（不再按供应商分组为二级列表）。同时调研“给没有读图能力的模型指定其它模型作为读图工具”的业界做法（本轮只调研不实现）。

## 过程记录

### 2026-08-12 14:30 CST

- 观点：移除“增加多个默认”功能；完全不要默认也在考虑范围内，但暂时保留默认（slot 1）。
- 依据：用户明确表述“把现在的那个增加多个默认的那个功能给去了。甚至考虑完全不要默认，但我觉得暂时还是先保留也可以”。
- 冲突：无。

### 2026-08-12 14:30 CST

- 观点：供应商行增加下拉按钮，展开可见该供应商已配置的模型列表；每个模型有独立编辑按钮，可做基础修改（显示名称、标签、图片输入、思考、上下文窗口、最大输出）。
- 依据：用户对设置页交互的直接要求；基础字段与 `PiProviderFormDialog` 既有模型字段保持一致。
- 冲突：无。

### 2026-08-12 14:35 CST

- 观点：标签（常用/快速/轻量等）作为替代“多个默认”的机制：模型可打多个标签；标签持久化在 models.json 的模型条目上（`PiGlobalModel.tags`）；标签为自由文本，设置页提供预设标签（常用/快速/轻量）与自定义输入。
- 依据：用户说明“打标签，这个功能相当于替代之前的多个默认”；标签需要跨设置页与会话页显示，属于全局模型配置而非会话/工作区状态。
- 冲突：与既有“默认槽位”语义无冲突（默认只保留 slot 1，槽位不再可增删）。

### 2026-08-12 14:40 CST

- 观点：“仅显示标签模型”为全局 UI 偏好，持久化于 `shellGui.mortise.showTaggedModelsOnly`（settings.json），由本地 RPC 读写（LOCAL_ONLY），不随远程工作区代理。
- 依据：该开关只影响 Mortise 渲染进程的模型选择器展示；`shellGui.<name>.*` 命名空间即为此类 shell UI 偏好设计（pi CLI 单独运行忽略）。
- 冲突：无。

### 2026-08-12 14:45 CST

- 观点：会话页模型选择器在开启“仅显示标签模型”且存在带标签模型时，展示单级标签模型列表（每行含供应商名与标签），选中即同时切换 provider+model；无标签模型不出现。未开启或没有带标签模型时维持原有两级（供应商→模型）或 flat 列表行为。
- 依据：用户明确要求“这样的显示下不用加供应商模型二级列表而是单级列表”。
- 冲突：无。

### 2026-08-12 14:50 CST

- 观点：给没有读图能力的模型指定“读图代理模型”的功能暂缓，先调研其它 agent（codex / DeepSeek-Reasonix / grok-build / oh-my-pi）的实现形式（工具调用 vs 配置切换 vs 其它）。
- 依据：用户指示“你先暂时放一下……目前先只做第一个改动，第二个改动只做调研，不修改”。
- 冲突：无。未形成共识，明确标记待决定。

## 最终共识

1. 移除“增加多个默认”（defaultSlots > 1 的增删入口）；全局默认仅保留 slot 1（defaultProvider/defaultModel/defaultThinkingLevel）。历史遗留的多槽位数据不再在设置页展示。
2. 模型标签（`PiGlobalModel.tags`，自由文本数组）成为替代多默认的轻量组织机制；预设建议 常用/快速/轻量，可自定义。
3. 供应商行新增“查看模型”下拉：列出该供应商全部模型，每个模型带编辑按钮，编辑对话框支持显示名称、标签、图片输入、思考、上下文窗口、最大输出。
4. “仅显示标签模型”为全局 UI 偏好（`shellGui.mortise.showTaggedModelsOnly`）：开启后会话页模型切换为单级标签模型列表，显示标签徽标；设置页提供开关。
5. 会话页模型选择器在正常模式下也为带标签模型显示标签徽标。
6. 读图代理模型（给无读图能力模型指定读图工具模型）：待决定，调研中。

## 调研结论（读图代理模型，待决定）

调研由并行会话完成，结论摘要：主流 agent（codex-rs 等）对图片处理采用“工具调用”形式——模型通过 image 工具（screenshot/read_image 类）读取图片并转成模型可消费的内容；没有发现“为无视觉模型显式指定另一个读图模型作为代理”的成熟先例。完整调研报告由 research-vision-model-patterns 会话产出，将作为后续“读图代理模型”功能设计的输入。

# 子智能体基础协议与扩展运行边界

状态：已达成共识

开始时间：2026-08-12 22:00 CST (UTC+08:00)

结束时间：2026-08-13 00:01 CST (UTC+08:00)

## 背景

现有核心子任务以 `spawn_session` 暴露，名称和参数容易让模型误解为普通 Session 创建；智能体配置虽已使用本地 Markdown，但仍存在前端管理入口，且缺少明确的上下文继承、异步等待和完成事件合同。同时需要为 Extension 自行实现后台智能体与用户编排工作流保留中立、自由的运行基础，而不把这些产品形态加入核心模型工具。

## 过程记录

### 2026-08-12 22:00 CST

- 观点：Mortise 需要区分当前 Session 的私有子智能体、脱离普通会话界面的后台智能体、用户编排的多智能体工作流。
- 依据：三者所有权、可见性和生命周期不同，但可以共享 Pi Agent Loop 与宿主运行能力。
- 冲突：既有 Automation 语义不提供脱离 Session 的核心 Isolated Agent target。

### 2026-08-12 22:35 CST

- 观点：可复用智能体配置使用本地文本文件；系统提示词和工具属于稳定配置，本次请求与可选父会话上下文由调用方另行提供。
- 依据：配置应由 AI 直接编写、选择和调用；当前不需要人工调用或编辑前端。
- 冲突：现有设置页包含子智能体配置管理界面。

### 2026-08-12 23:05 CST

- 观点：基础运行能力默认自由，不在核心增加 `read-only`、`write`、权限等级、结果文本审查或假设风险兜底；能力由实际工具、系统提示词和运行环境决定。
- 依据：框架应提供简洁、可组合的基础能力，强隔离或审查只作为调用方明确选择的独立能力。
- 冲突：调研候选方案中的能力分类与强制审批边界不作为 Mortise 核心语义吸收。

### 2026-08-12 23:30 CST

- 观点：核心只暴露一个 `subagent` 模型工具，直接替换 `spawn_session`；后台智能体与工作流由 Extension 注入工具并定义持久化、编排和展示。
- 依据：核心工具只表达当前 Session 私有委派；Extension 已能注册工具和后台能力，不应把扩展产品形态预设进核心协议。
- 冲突：旧工具名与部分实现名称带有 Session 创建含义，需要同步迁移且不双注册。

### 2026-08-13 00:01 CST

- 观点：`subagent` 默认异步启动并返回任务标识，通过同一工具的 `wait` 等待任一任务完成；支持本地配置、本次覆盖、`forkTurns`、可选结构化结果和七个生命周期动作。
- 依据：参考 Codex 的启动与等待分离，同时保持一个工具和简洁参数；完成通知进入所有者过程信息流，不伪造对话消息或自动触发 Turn。
- 冲突：现有前台/后台二态调用、`help=true` 和单一全局配置发现需要调整。

## 最终共识

- 核心模型工具命名为 `subagent`，只负责当前 Session 私有子智能体的 `start/list/inspect/message/resume/interrupt/wait`；`start` 立即返回任务标识，等待是独立动作。
- 智能体配置从全局 `~/.mortise/agent/agents/*.md`、Workspace `.mortise/agents/*.md` 和 Extension 只读定义发现；Workspace 同 ID 覆盖全局，Extension ID 保持命名空间。配置由 AI 直接维护，不提供子智能体配置前端。
- 配置承载系统提示词、工具和默认模型偏好；当前请求、`forkTurns` 上下文选择及本次覆盖独立传入。启动后保存最终配置和上下文选择快照。
- 子智能体完成及状态变化是父 Session 过程信息流事件，不是用户消息或助手最终回复，也不自动触发新 Turn。
- 核心运行协议默认自由，不增加权限或读写类别；可选 schema、预算、隔离等能力只在调用方明确请求时使用。
- 后台智能体与多智能体工作流不成为核心模型工具或核心前端。Extension 可以复用中立 Agent Run 服务，自行注册工具并拥有运行记录、YAML 工作流定义和界面。
- Automation 继续不把脱离 Session 的 Agent 作为核心 target；Extension 自有后台运行不等于新增第二套 Mortise Automation。

## 语义文档落点

- `docs/product-semantics.md` 的“主智能体、子智能体与配置”：记录核心工具、文件配置、上下文、完成事件及自由组合原则。
- `docs/product-semantics.md` 的“Extension 语义”：记录 Extension 可基于中立运行服务提供后台智能体和工作流。
- `docs/product-semantics.md` 的“Automations 语义”：澄清 Extension 后台运行不改变核心 Automation target 边界。
